# AGENTS.md

## Snapshot

- Astro 6 static portfolio with Tailwind CSS 4 and TypeScript; `astro.config.mjs` sets `output: 'static'`, `build.format: 'directory'`, and `trailingSlash: 'ignore'`.
- Site URL is `https://arnavpanigrahi.com`; custom domain comes from `public/CNAME` and GitHub Pages deployment.
- Package manager is pinned as `pnpm@10.33.2`; do not add `package-lock.json`.
- CI in `.github/workflows/deploy.yml` uses Node 22, runs `pnpm install`, then `pnpm build` on pushes to `main` and PRs.

## Commands

```bash
pnpm install   # install deps
pnpm dev       # dev server at http://localhost:4321
pnpm check     # astro check / type checking
pnpm build     # static build to dist/
pnpm preview   # preview built site
```

- There is no lint script and no test framework. After edits, run `pnpm check` then `pnpm build`.
- `pnpm deploy` builds, commits, and pushes. Do not run it unless explicitly asked.

## Content And Routes

- Homepage route: `src/pages/index.astro`, composed from `src/designs/folio/*` components.
- Homepage data lives in `src/data/content.ts` for profile/projects/skills/experience; update this instead of hardcoding section data.
- Blog posts live in `src/content/posts/*.md`; required frontmatter is enforced by `src/content.config.ts`: `title`, `author`, `published`, `source`, `guid`, optional `updated`, and `categories`.
- Blog routes are generated by `src/pages/posts/[...slug].astro`; post image rows can use `.post-image-row` and `.post-image-row--two`, styled there.
- Static assets go under `public/`. For assets referenced from Astro components, use `buildUrl()` from `src/utils/paths.ts` so `BASE_URL` is respected.

## Component Boundaries

- Page-level portfolio sections live in `src/designs/folio/`, not `src/components/sections/`.
- `src/designs/folio/Layout.astro` owns metadata, Google fonts, global design tokens, global CSS, reveal/parallax initialization, Lenis setup, cursor glow, and Oneko.
- `src/components/ui/Oneko.astro` is the small reusable widget component.
- The 404 page loads `public/js/notfound-model.js` as a module and passes `daruma.glb` via `data-model-url`; `public/js` is outside `tsconfig.json` and is not type-checked.

## Style And Type Quirks

- `tsconfig.json` enables `verbatimModuleSyntax` and `noUncheckedIndexedAccess`; use `import type` and guard indexed access.
- Supported aliases: `@/*`, `@components/*`, `@utils/*`, `@styles/*`.
- Existing Astro files keep imports at the top of frontmatter and mostly use relative imports.
- `.prettierrc` sets `printWidth: 120`, but `*.astro` uses `printWidth: 999`.
- Use CSS custom properties from `.folio-theme` in `Layout.astro` (`--c-accent`, `--font-serif`, `--ease-expo`, etc.) instead of hardcoded colors/fonts.
- Keep global CSS in `Layout.astro` or `src/styles/global.css`; section-specific CSS stays in the component.

## Animation And Navigation Gotchas

- GSAP, ScrollTrigger, Lenis, and SplitType are already installed; animations should respect `prefers-reduced-motion` like the existing components.
- `Layout.astro` wires Lenis into `gsap.ticker` and calls `ScrollTrigger.update` on scroll.
- `Nav.astro` uses fixed positioning; global `[id] { scroll-margin-top: 5rem; }` prevents anchor targets from hiding behind it.
- `.nav-mobile` must remain force-hidden at `min-width: 768px` with `!important` to avoid leaking after resize.
