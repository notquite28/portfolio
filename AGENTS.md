# AGENTS.md

## Snapshot

- Astro 6 static portfolio deployed to GitHub Pages; `astro.config.mjs` sets `site: 'https://arnavpanigrahi.com'`, `output: 'static'`, `build.format: 'directory'`, and `trailingSlash: 'ignore'`.
- Package manager is pinned as `pnpm@10.33.2`; use `pnpm-lock.yaml` and do not add `package-lock.json`.
- CI in `.github/workflows/deploy.yml` uses Node 22, runs `pnpm install` and `pnpm build`, then deploys `dist/` to Pages.

## Commands

```bash
pnpm install   # install deps
pnpm dev       # local Astro dev server
pnpm check     # Astro/type checking
pnpm build     # static build to dist/, also generates sitemap/rss
pnpm preview   # preview built output
```

- There is no lint script and no test framework. After code/content edits, run `pnpm check` then `pnpm build`.
- `pnpm deploy` builds, commits, and pushes. Do not run it unless explicitly asked.

## Content And Routes

- Homepage route is `src/pages/index.astro`; section data lives in `src/data/content.ts` for profile, projects, skills, and experience.
- Page-level portfolio sections live in `src/designs/folio/`; do not add new homepage sections under `src/components/sections/`.
- Blog posts live in `src/content/posts/*.md`; frontmatter schema in `src/content.config.ts` requires `title`, `description`, `author`, `published`, optional `updated`, and `categories`.
- Posts are first-party content on `arnavpanigrahi.com`; do not add Medium `source`/`guid` fields or describe them as mirrored posts.
- Blog routes are generated by `src/pages/posts/[...slug].astro`; RSS is generated by `src/pages/rss.xml.ts`.
- Post image rows can use `.post-image-row` and `.post-image-row--two`, styled in `src/pages/posts/[...slug].astro`.
- Static assets go under `public/`. In Astro components, reference assets through `buildUrl()` from `src/utils/paths.ts` so `BASE_URL` is respected.

## SEO And Metadata

- `src/designs/folio/Layout.astro` owns shared metadata, canonical URLs, RSS discovery, Open Graph/Twitter tags, JSON-LD injection, fonts, global CSS tokens, Lenis setup, cursor glow, and Oneko.
- Homepage passes `Person` JSON-LD from `src/pages/index.astro`; post pages pass `BlogPosting` JSON-LD and article Open Graph fields from `src/pages/posts/[...slug].astro`.
- `@astrojs/sitemap` generates `sitemap-index.xml`; `public/robots.txt` points crawlers to that sitemap.
- `public/CNAME` owns the custom domain; keep absolute production URLs on `https://arnavpanigrahi.com`.

## Style And Type Quirks

- `tsconfig.json` enables `verbatimModuleSyntax` and `noUncheckedIndexedAccess`; use `import type` and guard indexed access.
- Supported aliases are `@/*`, `@components/*`, `@utils/*`, and `@styles/*`.
- `.prettierrc` sets `printWidth: 120`, but `*.astro` uses `printWidth: 999`.
- Use CSS custom properties from `.folio-theme` in `Layout.astro` (`--c-accent`, `--font-serif`, `--ease-expo`, etc.) instead of introducing unrelated colors/fonts.
- Keep global CSS in `Layout.astro` or `src/styles/global.css`; section-specific CSS stays in the section component.

## Animation And Navigation Gotchas

- GSAP, ScrollTrigger, Lenis, and SplitType are installed; animations should respect `prefers-reduced-motion` like existing components.
- `Layout.astro` wires Lenis into `gsap.ticker` and calls `ScrollTrigger.update` on scroll.
- `Nav.astro` uses fixed positioning; global `[id] { scroll-margin-top: 5rem; }` prevents anchor targets from hiding behind it.
- Homepage section nav links should use root-relative anchors like `/#work` so they work from post pages.
- `.nav-mobile` must remain force-hidden at `min-width: 768px` with `!important` to avoid leaking after resize.

## Special Files

- The 404 page loads `public/js/notfound-model.js` as a browser module and passes `daruma.glb` via `data-model-url`; `public/js` is outside `tsconfig.json` and is not type-checked.
- Ignore `resume.tex` unless the user specifically asks about it; it is not part of the Astro site.
